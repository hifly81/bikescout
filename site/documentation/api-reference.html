RouteGeometry

FieldTypeDefaultDescription
coordinateslist[list[float]]... A list of GPS points in GeoJSON format. Each sub-list represents a coordinate triplet: [longitude, latitude, elevation]. This sequence is processed by the offline Terrain Truth Engine to cap implausible steps, smooth elevation, detect climbs and compute Haversine geodesic distances.

tactical_displaystring-Human-readable string with differential pressures, for example F: 20.0 PSI | R: 25.5 PSI (1.38/1.76 bar).

Pressure model: heuristic pneumatic volume/load model, not empirically calibrated. Reference pressure is scaled by total system mass (rider + bike) with a 1.25 exponent, tire width squared, wheel bead-seat diameter, rim internal width to the 0.5 power, casing stiffness and tube factor, then split across wheels with a 0.6 load exponent. Output is rounded to 0.5 PSI for actionability. Invalid inputs return an explicit Error instead of silently defaulting to unsafe values.

TOOL

geocode_location

Description

Primary resolution engine for geographical names. Finds latitude and longitude for any natural language place name (cities, mountain passes, specific addresses, or points of interest). Crucial Step: Use this tool to resolve coordinates before calling any routing or weather tools if you only have a location name.

Parameters

Parameter Type Status Description
location_name string Required The natural language name of the place (e.g., "Passo dello Stelvio", "Courmayeur").
language string Default: "en" Language for localized results (e.g., 'it', 'fr', 'es'). Maps to Accept-Language header.

Returns

GeocodingResponse
  • ● lat/lon: Precise floating-point coordinates for routing engines.
  • ● display_name: The full, formal localized name of the resolved location.
  • ● importance: A reliability score (0.0 to 1.0) to evaluate the match quality.
  • ● place_class/type: Contextual tags (e.g., 'city', 'mountain', 'peak') used to distinguish between different types of landmarks.
TOOL

trail_scout

Description

Advanced trail discovery engine. Returns comprehensive route data, technical difficulty assessment, navigation files (GPX), and visual altimetry reports. Supports both Round Trips (single point) and A to B routing. Synchronizes with weather and soil models to provide real-time tactical advice. If target_date is omitted, it defaults to the current day.

Single-route consistency: the orchestrator selects one ORS route (applying distance flexibility and the directional anchor, with up to three seeds when a bias is set) and passes that exact route feature to the surface analyzer. Surface composition, ascent, gradients and climbs are therefore computed from the same geometry used for the GPX track, tactical map and elevation profile — no second routing request is issued for surface analysis, so reported metrics never disagree with the exported route.

Verification prompt

Plan a gravel loop starting at latitude 45.0, longitude 10.0. Target about 40 km with a south-east directional bias, ride_character_first priority, and 20% distance flexibility. Use seed 42, complexity 5. Include surface analysis, GPX export, tactical map, and elevation profile. Give me the reported distance, ascent, max gradient, and climb list, plus the links to the downloaded files.

This exercises distance flexibility, the directional anchor and multi-seed selection. Verify that the reported distance_km, ascent_m and climb_list match the geometry in the downloaded GPX/map/elevation assets, and that only one routing pass is billed to ORS.

trail_scout_simple

Description

Flat-argument convenience wrapper around trail_scout for quick route generation. Only latitude and longitude are required; all other inputs have sensible defaults. It builds the rider, bike and mission models internally, so the same surface analysis, S-scale grading, TAEL™ mud risk and ASI pressure output are returned.

Tire setup defaults: when physical setup fields are omitted, defaults are derived from bike_type — Road 25mm/19mm/xc, Gravel 40mm/21mm/xc, MTB 58mm/25mm/trail, E-MTB 60mm/27mm/trail, and Enduro 60mm/28mm/enduro (tire width / rim internal width / casing). tubeless defaults to true; inner tubes add roughly 18% pressure. Every call returns MechanicalSetup.setup_details.tactical_display in F: ... PSI | R: ... PSI form.

Description

Cycling-specific weather assistant for real-time decisions and event planning. It provides local analysis of temperature, precipitation, wind and WMO conditions for the whole requested day. Analysis scope: the safety advice always scans every hourly slot of that day; target_hour only sets the reference conditions. Missing or inconsistent provider data returns an explicit Error instead of a [GO] verdict.

Parameter Type Status Description

Returns

TacticalForecastResponse
  • ● status: Confirmation of the API operation and data freshness.
  • ● error_message: Diagnostic reason when status is Error; absent on success.
  • ● metadata: Contextual data including timezone, resolved coordinates, source and analyzed hourly range.
  • ● tactical_forecast: Numeric hourly breakdown of temperature, rain probability, wind bearing and WMO condition.
  • ● reference_conditions: Verified reference-hour values and mean bearing after ride-window filtering.
  • ● safety_advice: Worst-hour wind risk and peak rain across the whole day, or an explicit [UNAVAILABLE] verdict when data is missing.

hydration_scout

Description

Physiological Intelligence Engine. This tool generates a mission-specific fueling strategy by cross-referencing localized weather dynamics (heat index, humidity, and solar radiation) with the predicted intensity of the effort. It calculates sweat rates and glycogen depletion to provide precise targets for fluids, carbohydrates, and sodium.
